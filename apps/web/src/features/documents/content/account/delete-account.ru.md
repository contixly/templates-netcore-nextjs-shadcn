# Удаление аккаунта

`/user/danger` запускает реализованный необратимый REST-сценарий полного удаления, а не soft-delete или фоновую очистку.

## Перед удалением

Проверьте провайдеров, сессии, организации, команды, приглашения и API-ключи. В транзакции организация, где пользователь единственный участник, может быть удалена; безопасные участия снимаются; удаление блокируется, если пользователь - единственный owner организации с несколькими участниками. UI предлагает передать/разделить владение только для этого точного блокера.

## Удалить аккаунт

1. Откройте `/user/danger`.
2. Точно введите текущий основной email.
3. Отправьте `DELETE /api/v1/account` с `{ "confirmationEmail": "..." }` и свежим CSRF.
4. После успеха покиньте защищенные страницы; ASP.NET Core удалит session cookie.

API проверяет подтверждение и авторизацию. Транзакция удаляет пользователя Identity и зависимые подтвержденные email, внешние логины, сессии, безопасные участия и настроенные зависимости через lifecycle stores и каскады базы. Браузер не удаляет записи напрямую.

## Вне scope

Экспорт, сроки хранения, восстановление и endpoint передачи владения не входят в этот сценарий. Продукт должен реализовать и документировать их до публикации удаления.
