# Сессии и безопасность

ASP.NET Core хранит браузерные сессии на сервере и отдает только безопасные метаданные. Секрет остается в защищенной HttpOnly cookie; исходные tickets и hashes не входят в REST-проекцию.

## Посмотреть сессии

`/user/security` вызывает `GET /api/v1/account/sessions?limit=20`. Элемент содержит непрозрачный id, метод аутентификации, признак текущей сессии, время и доступные IP/user-agent. Сначала идут недавние сессии. Страницы используют `nextCursor`; `limit` по умолчанию `20`, диапазон `1..100`.

Cursor - непрозрачное версионированное продолжение с обнаружением повреждения. Передавайте его без изменений, не выводите из него идентичность и начинайте с первой страницы после `invalid_cursor`.

## Отозвать доступ

- `DELETE /api/v1/account/sessions/{sessionId}` отзывает одну принадлежащую аккаунту не-текущую сессию.
- `DELETE /api/v1/account/sessions/others` удаляет остальные, сохраняя текущую.

Обе операции требуют cookie и свежий CSRF. После отзыва остальных UI загружает первую страницу из авторитетного состояния API.

## Граница безопасности

Чтения используют `no-store`; авторизация выводится из cookie, а не переданного браузером user id. Checksum cursor не является авторизацией: владение проверяется отдельно.
