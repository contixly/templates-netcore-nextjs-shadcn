# Профиль и подключения

Эти страницы - проекции REST API ASP.NET Core; браузер не читает таблицы Identity или токены провайдеров.

## Обновить отображаемое имя

1. Откройте `/user/profile`; страница загрузит `GET /api/v1/account`.
2. Измените отображаемое имя.
3. Сохраните через `PATCH /api/v1/account/profile` со свежим CSRF.

API обрезает и проверяет значение и возвращает обновленный аккаунт. Основной и дополнительные email доступны только для чтения. Проекция помечает основной адрес и провайдеров, которые сейчас подтверждают каждый верифицированный email.

## Управлять подключенными провайдерами

`/user/connections` загружает `GET /api/v1/account/connections`. Фиксированный каталог: Google, GitHub, GitLab, VK и Yandex. Challenge `connect` требует текущую сессию и полные runtime credentials провайдера; `signIn` - анонимный сценарий.

`DELETE /api/v1/account/connections/{provider}` запрещен для текущего метода аутентификации и если не останется другого подключенного, настроенного в runtime провайдера. Он удаляет локальную связь Identity; сохраненного токена для отзыва внешнего разрешения нет.

## Владение подтвержденным email

Нормализованные провайдерами email глобально уникальны. Внешний subject имеет стабильного владельца. Новый анонимный subject может связаться по email, только пока существующий провайдер подтверждает именно этот адрес. Конфликт возвращает безопасный Problem Details вместо слияния аккаунтов. Production-пароли и ручное управление email вне scope.
