# Для разработчиков

Используйте этот раздел при развитии сервиса на базе шаблона. В репозитории два runtime-приложения
с одной явной границей: ASP.NET Core владеет `/api/**`, аутентификацией, авторизацией,
бизнес-сценариями и хранением данных, а Next.js отвечает за рендеринг и взаимодействие в браузере.

## Структура репозитория

| Путь                                   | Ответственность                                                                               |
| -------------------------------------- | --------------------------------------------------------------------------------------------- |
| `apps/api/src/Template.Domain`         | Доменные value objects и правила без зависимостей от HTTP и инфраструктуры.                   |
| `apps/api/src/Template.Application`    | Сценарии использования и порты; зависит только от Domain.                                     |
| `apps/api/src/Template.Infrastructure` | Реализации портов для хранения, Identity, OAuth-клиента, криптографии и других внешних задач. |
| `apps/api/src/Template.Api`            | Единственный HTTP host; владеет Minimal API endpoints, граничной валидацией и авторизацией.   |
| `apps/api/tests`                       | Unit-тесты Application, API-тесты через `WebApplicationFactory` и E2E-оркестратор.            |
| `apps/web`                             | Отдельный UI на Next.js, использующий сгенерированный REST SDK.                               |
| `contracts/openapi/v1.json`            | Зафиксированный API-контракт, из которого генерируется TypeScript SDK.                        |

Зависимости направлены внутрь: Api и Infrastructure могут зависеть от Application, Application
зависит только от Domain, а Domain не зависит ни от HTTP, ни от инфраструктуры. Web-приложение не
импортирует backend-код и не обращается напрямую к базе или хранилищу аутентификации.

## Модель разработки

Начинайте изменение поведения с падающего точечного теста. Бизнес-правила размещайте в Domain или
Application, внешние задачи реализуйте в Infrastructure за портами Application, а обработчики
Minimal API оставляйте тонкими. Затем экспортируйте OpenAPI, перегенерируйте SDK и подключите
функцию Next.js через сгенерированную операцию.

Браузерная сессия хранится в защищенной HttpOnly cookie. Браузерные мутации получают свежий CSRF
токен и не сохраняют bearer tokens. Серверный рендеринг использует только серверный адрес API и
передает лишь явно разрешенный контекст запроса.

## Что держать согласованным

Изменение, видимое пользователю или потребителю API, может затронуть несколько зафиксированных
поверхностей:

- поведение Domain/Application и его точечные тесты;
- endpoint ASP.NET Core и покрытие через `WebApplicationFactory`;
- `contracts/openapi/v1.json` и `apps/web/src/lib/api/generated`;
- адаптеры и компоненты Next.js, Jest-тесты и сценарии Playwright;
- публичную документацию на английском и русском и историю релизов при публикации.

OpenSpec инициализирован, но намеренно не содержит активной возможности или change. Не создавайте
их без проектного решения или явного запроса на внедрение этого процесса.
