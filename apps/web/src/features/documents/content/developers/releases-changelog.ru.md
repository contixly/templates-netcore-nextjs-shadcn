# Релизы и журнал изменений

У публичной истории две поверхности: версионированные заметки к релизам и датированные еженедельные
сводки. Обе являются исходными страницами дерева документации; отдельного legacy-источника
релизных заметок для копирования нет.

## Заметки к релизам

Добавьте пару версии в
`apps/web/src/features/documents/content/history/releases/{version}.{locale}.md` или `.mdx`.
Описывайте проверенное поведение, доступное в этой версии: пользовательские процессы, API contracts,
изменения configuration или operations, security-relevant defaults и обязательные действия при
обновлении.

Не анонсируйте отложенную возможность. Если историческое поведение относится к прежнему full-stack
reference на Next.js, пометьте его как legacy, а не как текущее состояние целевого ASP.NET Core.
Синхронизируйте индекс релизов с реально опубликованными файлами.

## Еженедельные изменения

Добавьте парные датированные страницы в
`apps/web/src/features/documents/content/history/change-logs`. Стройте сводку по точному диапазону
commits и diff репозитория. Группируйте видимые пользователю результаты по возможностям; исключайте
предположения и внутренние детали, которые не влияют на пользователей шаблона.

Еженедельная сводка не заменяет долговременную документацию архитектуры, API, безопасности или
эксплуатации. При таком решении обновите подходящий файл `docs/` в том же изменении.

## Локализация и метаданные

Каждому production-visible URL истории нужны английский и русский варианты с эквивалентными
фактами, статусом, версией, датами и каноническими ссылками. Суффиксы локали остаются только в именах
исходных файлов. Используйте ту же строгую frontmatter policy, что и для других публичных страниц.

## Генерация и проверка

Из `apps/web`:

```bash
npm run content:generate
npm run content:check
npm run content:test
```

Проверьте оба зафиксированных результата:

- `apps/web/src/features/documents/generated/documents-registry.gen.ts`;
- `contracts/documents/search-index.json`.

Не редактируйте их вручную. Перед публикацией также запустите точечные тесты рендеринга/ссылок и
обычные web gates для types, tests и build.
