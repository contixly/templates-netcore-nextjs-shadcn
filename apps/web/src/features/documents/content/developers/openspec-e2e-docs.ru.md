# OpenSpec, E2E и документация

Держите согласованными требования, реализацию, тесты, сгенерированные контракты и публичную
документацию. Сейчас репозиторий использует migration plan и долговременные файлы в `docs/` для
утвержденных архитектурных, API, security, operations и migration-решений.

## Текущее состояние OpenSpec

OpenSpec инициализирован, но `openspec/specs` и активная область `openspec/changes` не содержат
capability или change. Не создавайте активный артефакт OpenSpec как обычную часть разработки.
Создавайте его только по явному запросу или проектному решению применить OpenSpec для изменения.

До этого источником требований служит принятая задача или design, а новое долговременное решение на
будущее нужно зафиксировать в подходящем файле `docs/` в том же изменении.

## Ведите реализацию через тесты

Начните с самого узкого падающего теста, который доказывает нужное поведение:

1. тесты Domain/Application для правил и сценариев;
2. API-тесты через `WebApplicationFactory` для HTTP-поведения и persistence integration;
3. проверки OpenAPI contract для формы и security операции;
4. Jest-тесты web adapter/component для поведения UI;
5. Playwright для полного браузерного сценария.

Зафиксируйте RED-падение до реализации. После минимального изменения запустите точечный GREEN-тест,
затем полные релевантные suites. Не используйте широкий E2E как единственное доказательство
бизнес-правила или HTTP boundary.

## Поддерживайте сгенерированные контракты

Изменение endpoint не завершено, если проходит только C#. Экспортируйте и проверьте
`contracts/openapi/v1.json`, выполните `npm run api:generate` и подтвердите `npm run api:check`.
Next.js должен использовать сгенерированную операцию и DTOs через REST adapters.

Изменения документации перегенерируют web registry и встроенный в API поисковый индекс:

```bash
cd apps/web
npm run content:generate
npm run content:check
npm run content:test
```

Не редактируйте вручную ни один сгенерированный артефакт документации.

## Добавляйте E2E на поддерживаемой границе

Спецификации Playwright находятся непосредственно в `apps/web/e2e`, общие helpers — в
`apps/web/e2e/support`. Используйте локальный automation flow ASP.NET Core и helpers сгенерированного
REST SDK. Подготавливайте данные через поддерживаемое API, избегайте прямых изменений базы и
отключайте secret-bearing artifacts там, где сценарий работает с одноразово показываемыми ключами.

## Обновляйте публичную документацию

Когда меняется поведение, видимое пользователю или потребителю API, обновите ближайшую каноническую
страницу в `apps/web/src/features/documents/content`. Опубликованной странице нужны парные варианты
`.en` и `.ru`. Сохраняйте канонические ссылки `/docs/...`, запускайте content compiler и добавляйте
релизную или еженедельную историю только после реальной публикации изменения.
