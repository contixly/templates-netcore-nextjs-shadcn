# How to write documentation

Source pages live under `apps/web/src/features/documents/content`. Write one clear user goal,
capability, explanation, or reference per canonical page, and create the English and Russian
variants together before publication.

## Use strict frontmatter

Every migrated production page requires this shape:

```md
---
title: "Page title"
description: "Short description for headers and search"
group: "General"
groupOrder: 400
parentItem: "Authoring"
parentItemOrder: 100
order: 10
status: "published"
toc: true
purpose: "Content authors"
author: "Template Maintainers"
version: "1.2.0"
editedAt: "2026-08-03"
---
```

`title`, `description`, `group`, and `parentItem` must be non-empty strings; `order` must be finite;
`toc` must be boolean; and `status` must be `draft`, `review`, `published`, or `archived`. The
production corpus also supplies non-empty `author` and `version` plus a real ISO date-only
`editedAt` value.

The optional allow-list is `groupOrder`, `parentItemOrder`, `purpose`, `hide`, `reading`, and
`source`. Unknown fields, invalid types or dates, duplicate canonical URL/locale variants, and an
unpaired production-visible page fail compilation. `published` and `archived` are production-visible
unless `hide: true`; `draft` and `review` are not.

## Name and structure the pair

Use `page.en.md` and `page.ru.md`, or `.mdx` when the page needs a custom component. Index variants
use `index.en.md` and `index.ru.md`. Keep equivalent facts, headings, status, navigation placement,
and related routes in both locales.

Each directory and filename route segment uses lowercase ASCII letters and digits with single `-`
or `.` separators; dots support version pages such as `0.0.11`. Uppercase, `_`, Unicode, spaces,
percent escapes, URL delimiters, and backslashes fail compilation before a route is generated.
The compiler removes one conventional terminal `/index`; repeated terminal aliases such as
`index/index` or `guide/index/index` are ambiguous and fail compilation.

Use a stable page shape: purpose first, then concepts or prerequisites, task steps or reference
facts, limits and failure behavior, verification, and related pages. The right table of contents is
built from `##` and `###` headings, including headings inside supported MDX containers. Footnote
reference numbers and images do not contribute to heading IDs, so every heading needs readable text.
Do not put `##` or `###` inside a footnote definition: GFM relocates referenced footnotes and omits
unreferenced ones. Ordinary footnote paragraphs, lists, links, code, and images remain supported.
Do not put `##` or `###` anywhere inside `Tabs` or `Tab`, because inactive tab content is unmounted
and cannot own a published fragment. `Tabs` contains only direct `Tab` element children, and every
`Tab` must be directly owned by `Tabs`; direct prose or wrapper components fail compilation.
Every `Tabs` block has at least one tab, direct `Tab.value` strings are unique, and a supplied
non-empty `Tabs.defaultValue` exactly matches one of those values.
Page/runtime markup reserves `document-title`, `main-content`, and
`footnote-label`; headings with one of those normalized IDs start at `-2`, and generated suffixes
never reuse an ID already claimed by another heading. Heading bases in GFM's dynamic
`user-content-fn-`/`user-content-fnref-` namespaces receive a `document-heading-` prefix.

## Use the closed MDX vocabulary

Plain Markdown is preferred. MDX accepts only these custom components:

- `Callout`;
- `Steps` and `Step`;
- `Files`, `Folder`, and `File`;
- `Tabs` and `Tab`;
- `DocumentLinkGrid`, `DocumentLinkGroup`, and `DocumentLinkCard`.

Executable MDX `import` and `export` syntax, flow/text expressions, JSX spreads,
expression-valued attributes, executable elements such as `script`/`iframe`, and unknown
components fail compilation. JSX attributes follow a closed per-element contract and must be quoted
strings: boolean shorthand, unknown attributes, missing or empty required custom attributes, and
duplicate attribute names or invalid variants fail compilation before rendering. Use
[Documentation components](/docs/general/authoring/sample) as the live fixture for supported rendering.
The `data-footnote-ref` JSX attribute is reserved for anchors generated by GFM.

## Add links and images

Internal document links use canonical `/docs/...` URLs without file extensions or locale suffixes.
The compiler verifies that the target page exists and that any heading fragment matches a generated
heading ID. Query strings are ignored for target lookup and every trailing slash is normalized the
same way during compilation and rendering. Keep English and Russian related-page routes identical.
`/docs/index` is the sole root alias; nested `/docs/.../index` and repeated `/docs/index/index`
links are rejected because no matching public route exists. Percent-encoded document path segments,
including encoded spellings of canonical characters, are noncanonical and rejected.

Keep Markdown reference labels unique. When a label is duplicated, the first definition wins, just
as it does during MDX rendering.

Use normal `https://` links for external material. Images use explicit `http://` or `https://`
sources, or an absolute `/img/...` path to a real file under `apps/web/public/img`. Relative paths,
protocol-relative sources, other local namespaces, and missing images fail compilation. Write
meaningful alt text, use a single `src` because `srcSet` is unsupported, and do not embed secrets,
credentials, or user data in examples or image artifacts.

Link targets cannot contain surrounding whitespace and must resolve to HTTP(S) or `mailto:`;
executable and malformed protocols fail compilation and are suppressed again during rendering.

## Generate and check artifacts

From `apps/web`, run:

```bash
npm run content:generate
npm run content:check
npm run content:test
```

`npm run content:generate` rewrites the committed TypeScript registry and JSON search index.
`npm run content:check` recompiles and byte-compares both outputs. Never edit
`src/features/documents/generated/documents-registry.gen.ts` or
`contracts/documents/search-index.json` by hand.

Before completion, also run the focused MDX/rendering tests, typecheck, full Jest suite, and
production build required by the change.
