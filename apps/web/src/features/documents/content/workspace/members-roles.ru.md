# Участники и роли

Участие имеет одну роль из закрытого `owner | admin | member`. ASP.NET Core возвращает capabilities и повторяет авторизацию каждой REST-операции.

## Встроенные роли

| Роль     | Авторизация                                                                                        |
| -------- | -------------------------------------------------------------------------------------------------- |
| `owner`  | Обновление/удаление организации, добавление участников, любая роль, команды/приглашения/ключи.     |
| `admin`  | Обновление, добавление, роли `member`/`admin`, команды/приглашения; без удаления и создания owner. |
| `member` | Только безопасное чтение организации, участников и команд.                                         |

Self/no-op, изменение owner администратором и потеря последнего owner блокируются. Команда не дает роль организации. Пользовательских ролей нет.

## Каталог участников

`GET /api/v1/organizations/{organizationId}/members?limit=50` возвращает `nextCursor`; лимиты `1..100`, cursors непрозрачны. Элемент содержит роль, время вступления, подтвержденный email/домен и признак вне политики. Чужие/отсутствующие организации не раскрываются.

## Добавление и изменение

Менеджер вызывает `POST /api/v1/organizations/{organizationId}/members` с существующим `userId`, допустимой ролью и требуемым подтверждением домена. Роль меняется через `PATCH /api/v1/organizations/{organizationId}/members/{memberId}` по текущему заблокированному состоянию. Нужны HttpOnly session и свежий CSRF.

Удаление участника организации намеренно не реализовано. Приглашения нужны новым пользователям, direct add - существующим аккаунтам.
