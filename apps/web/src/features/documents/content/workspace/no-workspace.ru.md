# Пользователь без рабочего пространства

У пользователя может быть ноль доступных организаций: новый пользователь, удаленный участник или получатель непринятого приглашения. Это нормальное состояние API.

## Что делает защитный механизм

Guard вызывает `GET /api/v1/organizations` через сгенерированный клиент. Пустая первая страница ведет на `/welcome`, где доступны:

- создание первого пространства через `POST /api/v1/organizations`;
- pending-приглашения через `GET /api/v1/account/invitations`;
- глобальные настройки аккаунта.

Создание атомарно добавляет участие owner и активную организацию. Accept приглашения атомарно добавляет участие, необязательную команду и то же предпочтение сессии.

## Что остается доступным

Глобальные страницы аккаунта и управления пространствами доступны без контекста организации. Деталь приглашения сохраняет нераскрывающую проверку основного email.

## Поведение панели

`/dashboard` сверяет предпочтение серверной сессии с доступными организациями. Если оно отсутствует/устарело, выбирается детерминированная доступная организация; если их нет - `/welcome`. Deep link проверяет `GET /api/v1/organizations/by-key/{organizationKey}`.

Браузер не создает фиктивные организации, не вставляет участия, не кеширует доступ в local storage и не использует прямую настройку базы/SQL. Защищенный Development/Test REST-helper подтверждения email существует только для автоматизации, не production-верификации. Реальный email приглашения вне scope.
