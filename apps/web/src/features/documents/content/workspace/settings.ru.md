# Настройки рабочего пространства

Настройки - REST-представления. Оболочка разрешает `GET /api/v1/organizations/by-key/{organizationKey}` и использует роль/capabilities ответа; видимость в клиенте не является авторизацией.

## Разделы настроек

| Раздел               | Маршрут                                    | Текущее поведение                                                    |
| -------------------- | ------------------------------------------ | -------------------------------------------------------------------- |
| Рабочее пространство | `/w/:organizationKey/settings/workspace`   | `PATCH`/`DELETE /api/v1/organizations/{organizationId}`.             |
| Участники            | `/w/:organizationKey/settings/users`       | Страницы/добавление существующих участников и допустимая смена роли. |
| Приглашения          | `/w/:organizationKey/settings/invitations` | Страницы/фильтр и создание приглашений на 48 часов.                  |
| Команды              | `/w/:organizationKey/settings/teams`       | Страницы команд и управление составом.                               |
| Роли                 | `/w/:organizationKey/settings/roles`       | Описание фиксированных ролей; пользовательские роли не реализованы.  |
| API-ключи            | `/w/:organizationKey/settings/api-keys`    | Отдельно документированное управление ключами организации.           |

Корень перенаправляет в первый доступный раздел после проверки доступа.

## Правила обновления и удаления

PATCH принимает измененные поля и отклоняет пустой/no-op body. Имя обрезается до 1-50 поддерживаемых символов. Slug нормализуется до максимум 64 строчных ASCII-букв/цифр с одиночными дефисами и не может выглядеть как UUID. UI отправляет только изменения к последней авторитетной детали.

Удаление доступно только owner и требует точное регистрозависимое имя в `confirmationName`. Недоступные ресурсы не раскрываются.

## Безопасность и scope

Каждая мутация использует сгенерированный клиент, защищенную HttpOnly cookie и свежий CSRF. Итерации 5-6 реализуют настройки organization/collaboration. Пользовательские роли, удаление участника, активная команда и отмена/повтор приглашения вне scope.
