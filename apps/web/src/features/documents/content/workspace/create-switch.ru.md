# Создание и переключение рабочего пространства

`/workspaces` работает через сгенерированные REST-вызовы организаций и не хранит отдельный браузерный список доступа.

## Создать рабочее пространство

1. Откройте `/workspaces` или `/welcome`.
2. Введите имя из 1-50 поддерживаемых Unicode-букв/цифр, пробелов, дефисов или подчеркиваний.
3. Отправьте `POST /api/v1/organizations` со свежим CSRF.

ASP.NET Core генерирует уникальный канонический slug и атомарно создает организацию, участие owner и предпочтение текущей сессии. Используйте канонический ключ ответа.

## Открыть рабочее пространство

`GET /api/v1/organizations?limit=50` возвращает доступные элементы и `nextCursor`; лимиты `1..100`, cursors непрозрачны. Маршруты используют `/w/:organizationKey/...`. UUID или старый slug разрешается через `GET /api/v1/organizations/by-key/{organizationKey}` с redirect на текущий slug при наличии доступа.

## Переключить контекст рабочего пространства

Выбор отправляет `PUT /api/v1/auth/session/active-organization` с UUID и свежим CSRF. Предпочтение живет в серверной сессии. Позже `/dashboard` использует его при наличии доступа; браузер не записывает доступ в local storage.

## Удалить рабочее пространство

Только owner отправляет `DELETE /api/v1/organizations/{organizationId}` с точным регистрозависимым `confirmationName` и CSRF. Удаление очищает ссылки в сессиях и не выбирает другое пространство неявно.
