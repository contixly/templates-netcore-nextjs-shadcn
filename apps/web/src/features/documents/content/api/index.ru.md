# API-доступ

ASP.NET Core — единственный HTTP-хост для `/api/**`. UI Next.js вызывает его через generated REST SDK и не владеет API-маршрутами, сессиями, бизнес-логикой или доступом к базе.

## Границы учетных данных

| Клиент          | Учетные данные                                     | Поверхность                                                      |
| --------------- | -------------------------------------------------- | ---------------------------------------------------------------- |
| Браузерный UI   | Защищенная same-origin session cookie с `HttpOnly` | Аккаунт, организации, совместная работа и управление API-ключами |
| Машинный клиент | Ровно один заголовок `x-api-key`                   | Поддерживаемые read-only операции `/api/v1`                      |

Браузерный JavaScript никогда не читает cookie и не хранит bearer token. Управление API-ключами — операция с браузерной сессией; создание, изменение, ротация и отзыв также получают свежий токен через `GET /api/v1/auth/csrf` и отправляют `X-CSRF-TOKEN`. API-ключ не может управлять ключами.

Некоторые операции чтения организаций принимают любой вид учетных данных. При наличии `x-api-key` выбирается только аутентификация API-ключом; валидная cookie не компенсирует невалидный ключ.

## Текущая машинная поверхность

Итерация 7 поддерживает `GET /api/v1/me`, список и детали организаций, участников, команды и участников команд. Успешный JSON использует `{ "data": ... }`. Ошибки используют RFC Problem Details как `application/problem+json`; решения принимаются по HTTP-статусу и стабильному `code`.

## Правило клиента

Адаптеры приложения вызывают операции generated SDK и импортируют generated DTO. Не добавляйте raw `fetch`, рукописные транспортные типы, Server Actions, API Route Handlers или прямой доступ к базе. `contracts/openapi/v1.json` — зафиксированный контракт, а генерируемый output проверяется на детерминированность.
