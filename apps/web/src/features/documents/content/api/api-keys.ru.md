# Управление API-ключами

API-ключи аутентифицируют машины на поддерживаемой read-only поверхности `/api/v1`. Управление остается за защищенной браузерной сессией с `HttpOnly` и свежей CSRF-защитой.

## Владельцы и маршруты

| Владелец     | Страница браузера                        | REST-коллекция                                    |
| ------------ | ---------------------------------------- | ------------------------------------------------- |
| Пользователь | `/user/api-keys`                         | `/api/v1/account/api-keys`                        |
| Организация  | `/w/{organizationKey}/settings/api-keys` | `/api/v1/organizations/{organizationId}/api-keys` |

Каждый аутентифицированный пользователь может управлять личными ключами. Для организации нужна доверенная возможность `canManageApiKeys`. Ключ организации остается привязан к ней независимо от последующего участия создателя.

## Создание и хранение

Для создания нужны имя, один или несколько элементов закрытого набора presets, срок действия и явные параметры fixed-window. Предложения UI — только удобство; определяющим остается REST-тело.

Только успешные создание и ротация показывают исходный ключ ровно один раз. Скопируйте его в одобренный менеджер секретов до закрытия окна. Не помещайте ключ в исходный код, URL, браузерное хранилище, логи, аналитику, скриншоты или traces.

Сервис хранит только SHA-256 hash ключа, безопасные метаданные и несекретный 16-символьный префикс `start`. Списки, изменение, отзыв, `/api/v1/me` и чтение ресурсов не возвращают ключ или hash.

## Изменение, ротация и отзыв

Можно менять имя, presets, срок, enabled и rate-limit. Пропущенные поля сохраняются; no-op возвращает `409 api_key_update_unchanged`.

Ротация сохраняет логический ID и конфигурацию, атомарно делает старый ключ невалидным, сбрасывает текущее окно/счетчик, сохраняет `lastRequestAt` и один раз показывает замену. Отзыв делает ключ невалидным и удаляет из последующих списков; повтор возвращает `404 api_key_not_found`.

Небезопасные вызовы сначала получают `GET /api/v1/auth/csrf` и отправляют `X-CSRF-TOKEN` с session cookie. API-ключи не могут вызывать маршруты управления.
