# Template documentation

This template is a two-application system. ASP.NET Core 10 is the only HTTP host for `/api/**` and
owns authentication, authorization, business use cases, persistence, and OpenAPI. The separate
Next.js application owns rendering and browser interaction and accesses product data only through
the generated REST SDK.

Browser sessions stay in a secure same-origin HttpOnly cookie. The UI does not store bearer tokens,
call Server Actions for product behavior, host product API Route Handlers, use Better Auth or
Prisma, or access the database directly.

## What the current template includes

- **Layered .NET 10 backend**: `Template.Domain`, `Template.Application`,
  `Template.Infrastructure`, and the sole HTTP host, `Template.Api`.
- **REST-only web boundary**: a separate Next.js UI consumes the committed OpenAPI contract through
  generated operations and DTOs.
- **Accounts and sessions**: ASP.NET Core Identity-backed accounts, persistent sessions, optional
  external OAuth connections, CSRF protection, and secure same-origin cookies.
- **Organizations and collaboration**: canonical workspace routes, fixed roles, members, teams,
  invitations, email-domain policy, and no-workspace onboarding.
- **API access**: personal and organization API keys, one-time secret reveal, rotation, permissions,
  expiration, rate limits, and supported read-only `/api/v1` routes.
- **Public documentation**: canonical `/docs/**` routes, English and Russian variants, search,
  release history, and weekly change records.
- **Quality workflow**: .NET unit and `WebApplicationFactory` tests, Jest, Playwright, deterministic
  OpenAPI and documentation artifacts, and boundary checks.
